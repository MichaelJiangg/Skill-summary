---

## 一、产品概述

「一张图摘要」是一个内置于 Claude 对话中的 Skill，能够将任意文章、会议纪要、研究报告自动转化为一张**结构化图文摘要卡片**，输出为可直接截图分享的 HTML 文件，支持一键下载高清 PNG。

### 核心价值

- **5秒懂全文**：结论先行设计，扫一眼标题+总结即可判断是否需要深读
- **零排版成本**：输入原文，输出即用，无需手动整理和排版
- **跨场景通用**：会议纪要、产品文章、读书笔记、研究报告均适用

---

## 二、触发方式

在 Claude 对话中，提供文章内容后使用以下任意触发词：

```
图文纪要 / 一图总结 / 摘要卡 / 可视化摘要 / 做成卡片 / 钉钉风格总结
```

**示例：**
```
把这篇文章做成一张图
帮我图文纪要一下这份会议记录
/article-visual-summary 将下面的文字转换成1张图模式
```

## 五、各区块说明

### 5.1 基础信息条

位于标题和总结之间，呈现文章的元数据。

- **位置**：Header 内，副标题正下方
- **样式**：无背景色，上下细线分隔，标签大写浅灰，value 中灰加粗（弱视觉，不抢总结权重）
- **字段数**：3～6 个，等宽排列
- **适配规则**：

| 内容类型 | 推荐字段 |
|---|---|
| 会议纪要 | 会议主持 / 参会人数 / 会议时长 / 当前阶段 / 下次会议 |
| 文章报告 | 文章类型 / 核心主题 / 数据来源 / 发布时间 / 适用场景 |
| 读书笔记 | 作者 / 类型 / 核心设定 / 章节数 / 核心命题 |
| 面试记录 | 姓名 / 应聘职位 / 工作年限 / 学历 / 当前状态 |

### 5.2 总结条（结论先行）

**这是整张图最重要的设计原则。**

- **位置**：基础信息条下方，Section 01 正上方
- **样式**：浅蓝背景 `#EFF4FF`，蓝色圆角边框，`✏️ 总结` 标题 17px 与 Section 编号等大
- **内容要求**：
  - ✅ 必须是**判断句/结论句**，不能是描述句
  - ✅ 优先提炼 1 个核心判断 + 1 个关键行动方向
  - ❌ 错误示例："本文介绍了降准政策的相关内容"
  - ✅ 正确示例："降准释放1万亿，短期利好房贷族，存款利息随之缩水；理性规划财务比盲目跟风更重要"

### 5.3 Section 01：主体卡片

每张卡片的内部结构：

```
[图标] 标题文字  [Badge标签]
───────────────────────────
· 要点 1（关键词高亮）
· 要点 2
· 要点 3（最多5条）
───────────────────────────
斜体 Insight 总结语（判断句，非描述句）
```

**列数规则：**
- 3 个主题 → 3列（默认）
- 4～5 个主题 → 5列（字号自动缩小）

### 5.4 Section 02：汇总网格

双行网格结构，用颜色区分信息性质：

| 行 | 底色 | 适用内容 |
|---|---|---|
| 上行 | 浅蓝 `#F5F8FF` | 正向/事实/已确认信息（决策、成果、优势） |
| 下行 | 浅橙 `#FFF8F0` | 风险/待处理/待跟进信息（短板、问题、待验证） |

每行格数可独立设置，上行 2～4 格，下行 1～3 格。

### 5.5 Section 03：小结 + 建议

两行结构：

- **第一行（全宽）**：综合结论段落，蓝色背景，≤120字，含行内高亮
- **第二行（3列）**：建议卡片，绿色背景，每卡含图标 + 标题 + 正文，按受众/场景分类

## 六、视觉语言系统

### 6.1 Badge 颜色语义

| 颜色 | class | 含义 | 使用场景 |
|---|---|---|---|
| 🔵 蓝 | `badge.blue` | 参考/背景/信息 | 数据说明、参考项 |
| 🟢 绿 | `badge.green` | 完成/正向/已确认 | 已决策、达标、优势 |
| 🟠 橙 | `badge.orange` | 进行中/待跟进 | 筹备中、跟进中 |
| 🔴 粉 | `badge.pink` | 风险/待处理/问题 | 风险项、待整合 |
| 🟣 紫 | `badge.purple` | 类别/领域分类 | 技术原理、业务方向 |

### 6.2 行内高亮规则

在要点文字中，对关键词加色标注，**每句最多 1～2 个词**，不整句高亮。

| class | 颜色 | 用于 |
|---|---|---|
| `hl-blue` | 蓝 | 工具名、产品名、专有名词 |
| `hl-orange` | 橙 | 数字、量化指标、交付物、截止时间 |
| `hl-red` | 红 | 风险词、问题描述、负面结论 |
| `hl-green` | 绿 | 正向结论、达标表现 |
| `hl-purple` | 紫 | 方法论、框架、类别词 |

### 6.3 Insight 语写作规范

每张主体卡片底部必须有一句 Insight，要求：
- **≤ 20字**，斜体，颜色与卡片 badge 一致
- **必须是判断句**，不是对上方内容的重复描述
- 格式：`主语 + 判断/方向`

| ❌ 描述句（错误）| ✅ 判断句（正确）|
|---|---|
| "以上是本卡片的要点" | "信号意义大于短期资金效应" |
| "介绍了三个方面" | "技术路径清晰，稳定性是首要挑战" |

## 八、使用步骤

**Step 1：准备内容**
将文章/会议记录/报告全文粘贴进对话，或上传文件（支持 .txt / .pdf）。

**Step 2：触发 Skill**
在消息末尾加上触发词，例如：
```
帮我做成图文纪要
```

**Step 3：等待生成**
Claude 会自动完成：内容解析 → 结构规划 → HTML 生成 → 文件输出，约 30～60秒。

**Step 4：下载使用**
- 点击对话中的文件链接，浏览器打开 HTML
- 点击右上角 **「⬇ 下载为图片」** 按钮，保存高清 PNG
- 也可直接 `Ctrl+P` / `⌘P` 打印为 PDF

## 十、注意事项

1. **结论先行条不能写成描述句**，写"本文介绍了…"会被 Claude 内部检查拒绝
2. **每张卡片必须有 Insight**，不能留空，否则视觉节奏断裂
3. **行内高亮每句最多 2 个词**，过多高亮等于没有高亮
4. **汇总网格列数必须与实际格数一致**，否则布局错位
5. **内容不足时不要编造**：要点不够 5 条就写 3 条，不要凑字数
6. **下载 PNG 时渐变文字已用 SVG 实现**，截图不会出现色块背景问题（已修复 html2canvas 兼容问题）
